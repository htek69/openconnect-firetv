# 手動テスト手順と実機での観測結果（Fire TV）

このドキュメントは、TV UI（リモコンだけで完結する D-pad 操作）と接続の通し確認について、
**実機で実際に行った手順と、そのとき観測した値**を、利用者が再現できる形に書き起こしたものである。

- 実機: **Fire TV Stick 4K（API 25 / 1920x1080）**、リモコンのみで操作
- 対象ビルド: 各節に記載。最終確認は **`b60606e`**
- ここに「✅ 確認済み」と書いてあるものは**すべて実機で観測した結果**である。
  観測していない項目は最後の「未確認の項目」にまとめてあり、そこに挙がっているものは
  **確認していない**。

座標（`[左,上][右,下]`）は `uiautomator dump` で読み取ったフォーカス矩形で、1920x1080 での値である。
利用者が手順を再現するときに座標は不要で、フォーカスがどこに乗るかの根拠として残してある。

---

## 0. 前提

1. `docs/BUILD.md` の手順で `app-debug.apk` をビルドし、端末にインストールする。
2. ホーム画面（アプリ一覧）から本アプリを起動する。
3. **端末の言語は `en-US` にしておく。** `ja-JP` では端末側の IME が
   `libWnnWrapper.AMAZON.so` を読めず `UnsatisfiedLinkError` で落ちることを観測した
   （端末側の欠落であり、本アプリの問題ではない）。`en-US` ではこのクラッシュは起きず、
   ASCII が変換されずそのまま入る。
4. **ソフトキーボードが出ないときは、まず端末を再起動する。** IME ウィンドウが
   `Surface: shown=false` のまま居座って BACK を食い続ける状態を観測しており、
   再起動で復旧した（節 1 の脚注参照）。

## 1. 接続先の追加（文字入力とソフトキーボード） ✅ 確認済み

**手順**（リモコンのみ。ビルド `5f5cfdc` 以降で確認）

1. ホーム画面で `＋ 接続先を追加` にフォーカスを合わせ、決定。
2. 初期フォーカスは `サーバ URL（例: vpn.example.com）` の**行**に乗る
   （テキスト欄そのものではない）。ここで決定を押す。
3. ソフトキーボードが出る。`test.example.com` を入力する。
4. **BACK を1回** → キーボードが閉じる。
5. **BACK をもう1回** → 編集モードが終わり、行にフォーカスが戻る。**入力値は保持される。**
6. DOWN → `表示名（任意）` の行。
7. DOWN → `保存`。決定。
8. 一覧に `test.example.com` が現れる。

**観測結果**

- 手順3 でキーボードが出ていることの判定は、画面を見るか、
  `dumpsys window` の `InputMethod` ウィンドウの `mViewVisibility=0x0(VISIBLE)` と
  `mHasSurface=true` で行う。**`screencap` は IME レイヤを含まないので判定に使えない。**
- BACK が2回必要なのは正しい（1回目は IME が消費して閉じる、2回目が編集モード終了）。
- 保存後のプロファイルに `batch_mode=empty_only` と `server_address=test.example.com` が
  書かれていることを、`profile-<uuid>.xml` を読んで確認した。この値が無いと再接続ごとに
  認証ダイアログが出て自動フェイルオーバーが止まる（仕様書 9.2）。
- **表示名を空のまま保存すると、表示名はサーバ URL から導出した既定名になる**
  （`test.example.com` → `Example`）。

> 脚注（キーボードが出ない場合）: 本アプリ側の必要条件は「明示的な表示要求」で、
> `showSoftInput(editText, 0)` を使っている（暗黙要求 `SHOW_IMPLICIT` では
> Fire TV のフルスクリーン IME が要求を拒否することを実機で確定させた）。
> それでも出ない場合は端末側の IME が壊れている可能性があり、再起動の前後で
> `Surface: shown` が `false` → `true`、`mDrawState` が `READY_TO_SHOW` → `HAS_DRAWN`
> に変わることを観測している。

## 3. グループの作成・編集画面 ✅ 確認済み

### 3-1. 作成経路（候補3件、`0e3d460`）

DOWN×5 で `[96,951][217,1047]` **`保存`**、RIGHT で `キャンセル`、LEFT で `保存`、
UP で最後の候補。**4方向すべて期待どおり。**

### 3-2. 編集経路（メンバー3件・候補0件、`78dbee8`）

3つのボタンが画面内に出ていることを確認した:

```
保存 [128,960][185,993] / キャンセル [281,960][422,993] / グループを削除 [518,960][713,993]
```

| 入力 | 着地 |
|---|---|
| DOWN×5 | `[96,928][217,1024]` **`保存`** |
| RIGHT / RIGHT | `キャンセル` → `グループを削除` |
| LEFT / LEFT | `キャンセル` → `保存` |
| UP | 最後のメンバー行の `▲` |
| さらに DOWN | 据え置き（先頭行への巻き戻りは起きない） |

**確認すべき点: メンバーや候補が増えてもボタン行が画面外に落ちないこと。**
以前はメンバー3件＋候補1件で、`保存`/`キャンセル`/`グループを削除` の文字が
`uiautomator dump` に1つも現れず、フォーカスだけが画面外へ移っていた。

### 3-3. グループ行の長押し ✅ 確認済み（`17ec5c6`）

ホーム画面でグループの行を長押しするとグループ編集画面へ入る。

フォーカスはグループ名の**行**（`[96,193][1824,289]`）に乗る。

## 4. 接続先の削除（確認オーバーレイ） ✅ 確認済み（`2e8c68b` / `df65a4b`）

**手順**: ホーム画面で接続先の行を**長押し**する → 確認オーバーレイが出る →
`キャンセル`（初期フォーカス）か `削除する` を選ぶ。BACK でも取り消せる。

| 確認項目 | 観測結果 |
|---|---|
| 長押しして指を離しても確認が残る | ✅ |
| 決定（`キャンセル`）で取り消せる | ✅ プロファイル数は変わらない |
| RIGHT → 決定（`削除する`）で削除される | ✅ `削除する [660,535][837,631]` で削除され、一覧から消えた |
| BACK で閉じるだけ（画面も離脱しない） | ✅ プロファイル数は変わらない |
| オーバーレイ表示中の DOWN / UP | ✅ `キャンセル` から動かない（背後の行へ漏れない） |

**閉じた後のフォーカス**（`df65a4b`）:

| 閉じ方 | 閉じた後のフォーカス |
|---|---|
| 決定（取り消し） | `[96,443][412,649]` = **長押しした行に復帰** |
| BACK | `[96,443][412,649]` = 同上 |
| 削除実行 | `[96,882][433,1016]` = `＋ 接続先を追加`（消えた行の次に来た行） |

**確認すべき点: 閉じた後にフォーカスがどこにも無い状態にならないこと。**
以前はどの閉じ方でも `focused="true"` が0個になり、リスト操作ができなくなっていた。

削除しようとした接続先がグループに含まれている場合、確認オーバーレイがそれを警告することも
確認した（実際に観測した文言）:

```
「myvpn」を削除しますか？ この接続先は次のグループに含まれています: 「テスト群」。
削除すると自動的にグループから外れます。
```

## 5. 設定画面 ✅ 確認済み（`b60606e`）

**手順**: ホーム画面の `設定` から入り、DOWN を押し下げていく。

| 入力 | フォーカス | 該当要素が画面内にあるか |
|---|---|---|
| 初期 | 宛先ホストの行 | ✅ |
| DOWN #1 | 宛先ポートの行 | ✅ |
| DOWN #2 | プローブ間隔の `＋` | ✅ |
| DOWN #3 | 失敗閾値の `＋` | ✅ |
| DOWN #4 | `[96,316][301,412]` | ✅ `設定を保存 [121,346][276,383]` |
| DOWN #5 | `[96,434][516,552]` | ✅ `VPN の許可を取得する [119,472][493,514]` |
| DOWN #6 | `[96,592][417,710]` | ✅ `VPN を切断する [124,630][389,672]` |
| DOWN #7 | `[96,750][639,896]` | ✅ `詳細設定とログ [113,787][622,829]` |

## 6. 接続の通し確認 ✅ 確認済み（`b60606e`）

**手順**

1. 接続先を3件追加する（この確認では `unreachable` / `v-server` / `myvpn`）。
2. グループを1つ作り（この確認では `テスト群`）、候補を**優先順**に並べる:
   `unreachable` → `v-server` → `myvpn`。`自動切替: ON`。
3. ホーム画面でそのグループの行に決定を押して接続する。
4. グループ行のバッジと、`tun0` の状態を時間を追って観測する。

**観測結果**

```
[15s] 接続中 (unreachable)        tun0: なし
[30s] 接続中 (unreachable)        tun0: なし
[45s] 疎通確認中 (v-server)       tun0: inet 10.10.10.38
[60s] 接続済み (v-server)         tun0: inet 10.10.10.38
...   [300s] まで安定
```

先頭候補（`unreachable`）では `tun0` が張られず、次候補（`v-server`）でトンネルが張られ、
`疎通確認中` → `接続済み` と進み、300秒まで安定していた。
**画面に出ている候補名とバッジが、実際の `tun0` の状態と一致している**ことをこの観測で確認した。

なお、接続状態の表示がホーム画面に追従すること自体は別の機会にも確認している
（`接続中 (unreachable)` → `接続済み (v-server)`）。Fire TV には通知シェードが無いため、
接続状態はこのグループ行の表示だけが手がかりになる。

## 7. 未確認の項目（**確認していない**）

以下は実機で観測していない。ここに挙がっているものについて「動く」と判断してはならない。

1. **`ConsentRequiredScreen`（VPN 許可を求める画面）。**
   確認に使った端末では VPN 許可が既に付与されていたため、この画面に到達していない。
   再現には端末の許可設定を取り消す必要があり、利用者の端末設定を変更することになるので
   行っていない。設定画面の `VPN の許可を取得する` を押す経路も、
   **許可済みの応答（「すでに許可されています」）を含めて未確認である。**
2. **長時間放置テスト（RK4）。** 実施記録が無い。
   画面消灯中は切断し点灯時に繋ぎ直す設計（消灯中は常に待機中）だが、
   その通し確認は行っていない。
3. **シナリオ③（安全策 S2: 下層ネットワークが落ちている間は切り替えない）。** 未確認。
4. **稼働中のトンネルがプローブ失敗で切り替わる経路。**
   節6 で観測したのは「接続開始時に先頭候補が繋がらず次候補へ進む」ところまでである。
   `接続済み` になったあとにトンネルを落として切り替わるところは観測していない。
5. **接続先を削除したときに、稼働中のエンジン側でも候補が外れること。**
   この経路（削除を既定 SharedPreferences の世代キー経由で再読込に載せる）は
   JVM のユニットテストでのみ確認しており、実機では未確認である。
6. **グループの削除の確認オーバーレイ**（グループ編集画面の `グループを削除`）。
   接続先の削除（節4）は実機で確認済みだが、グループ側の確認オーバーレイと、
   取り消して閉じたあとに `グループを削除` ボタンへフォーカスが戻ることは未確認である。
   **裁定87**: 裁定86 の最初の実装（外側 `Column` の
   `focusProperties { canFocus = !pendingDelete }`）は、確認オーバーレイを出して
   いない**通常状態**のグループ編集・作成画面で `DOWN` 2手目にフォーカスが消える
   回帰を起こした（実機で計測。節3 の 3-1/3-2 が到達できなくなった）。継承に
   頼るのをやめ、オーバーレイ表示中は**背後のツリーを組み立てない**形に変えた。
   その結果、**確認オーバーレイの暗幕の裏に背後の画面は見えない**
   （グループ編集画面のみ。接続先の削除＝節4 のオーバーレイは従来どおり背後が
   見えている）。節3 の再計測と、この見え方が受け入れられるかの確認が要る。
7. **グループ編集の保存エラー表示**（`グループ名を入力してください` /
   `候補を1件以上選んでください`）、および**表示名を空にしたときの案内文**。

## 8. 計測に使った道具（再現の補助）

利用者が画面を見て確認する分にはリモコンだけで足りる。開発時に使った計測手段を参考に残す。

- `adb shell uiautomator dump` — フォーカス矩形と、画面に実際に描かれている文字の一覧。
  「ボタンが画面外に落ちている」類の欠陥はこれで検出した。
- `adb shell dumpsys window` — IME ウィンドウの `mViewVisibility` / `mHasSurface`。
  **ソフトキーボードが出ているかの判定はこれで行う**（`screencap` は IME レイヤを含まない）。
- `adb shell sendevent /dev/input/event4 …` — 本物のリモコンと同じキー経路。
  `adb shell input keyevent` は IME に届かない。選択キーは **`KEY_KPENTER` (96)**。
- `adb logcat -s FailoverService:D` — 画面の消灯・点灯、プロセス kill からの復帰、
  wake lock の取得・解放。
